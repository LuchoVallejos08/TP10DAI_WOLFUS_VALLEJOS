Los errores

1src/app.jsMiddleware

El problema

Faltaba app.use(express.json()), así que req.body llegaba undefined y register/login tiraban 500.

Cómo lo detecté

POST /register devolvía 500: “Cannot destructure property 'name' of req.body”.

La solución

Agregué express.json() antes de montar los routers.

2src/app.jsRouting

El problema

El router de auth estaba montado en /api/loginn (doble “n”): las rutas no existían en el path esperado.

Cómo lo detecté

Pegar a /api/login/... daba 404; en app.js vi el typo.

La solución

Cambié el prefijo a /api/auth.

3src/utils/token.jsConfig

El problema

module.export (sin la “s”): signToken no se exportaba y quedaba undefined.

Cómo lo detecté

Al llamarlo desde el controller reventaba; leyendo el archivo vi el typo.

La solución

Lo corregí a module.exports.

4src/utils/token.jsConfig

El problema

El token se firmaba con process.env.JWT_SECRETT (doble “T”), una variable que no existe.

Cómo lo detecté

Comparé el nombre con el .env (JWT_SECRET) y no coincidían.

La solución

Usé process.env.JWT_SECRET.

5src/utils/token.jsJWT

El problema

El token expiraba en 2 segundos (expiresIn: '2s'): quedaba inválido casi al instante.

Cómo lo detecté

Vi el valor '2s' al leer signToken.

La solución

Le puse una duración útil de '1h'.

6src/utils/token.jsJWT

El problema

El payload no incluía el id del usuario, pero las rutas protegidas lo necesitan.

Cómo lo detecté

En /me el controller usaba req.user.id y venía undefined.

La solución

Agregué el id al payload: { id, role }.

7src/routes/userRoutes.jsMiddleware

El problema

En GET /me el orden estaba invertido: corría el handler antes de autenticar.

Cómo lo detecté

Vi get('/me', getProfile, authMiddleware) y que /me crasheaba sin token.

La solución

Puse authMiddleware primero.

8src/middleware/authMiddleware.jsJWT

El problema

Se usaba jwt.decode, que no valida firma ni vencimiento: cualquier token falso pasaba.

Cómo lo detecté

Con un token inventado la ruta protegida respondía OK.

La solución

Reemplacé por jwt.verify(...) dentro de un try/catch.

9src/middleware/authMiddleware.jsJWT

El problema

La condición (!token || decoded) dejaba pasar a todos, incluso sin token.

Cómo lo detecté

Sin mandar token, la ruta no me frenaba.

La solución

Reescribí la lógica: sin token o inválido corta; solo pasa si verify es válido.

10src/middleware/authMiddleware.jsHTTP

El problema

Para token faltante o inválido devolvía 403 en vez de 401.

Cómo lo detecté

Vi el res.status(403) y lo comparé con lo que pide la consigna.

La solución

Cambié la respuesta a 401 (no autenticado).

11src/controllers/authController.jsFlujo

El problema

En register, el 400 por datos faltantes no tenía return: seguía ejecutando.

Cómo lo detecté

Leyendo el código vi que después del 400 continuaba con el handler.

La solución

Agregué el return faltante.

12src/controllers/authController.jsHTTP

El problema

Registrar un email ya existente devolvía 200 (éxito) en vez de error de validación.

Cómo lo detecté

Repetí un register y me daba 200.

La solución

Lo cambié a 400.

13src/controllers/authController.jsFlujo

El problema

En login, email inexistente respondía 200 y sin return, y crasheaba al comparar contra null.

Cómo lo detecté

Con un email que no existe el server tiraba 500.

La solución

Devuelvo 401 con return cuando el usuario no existe.

14src/controllers/authController.jsLogin

bcrypt.compare con los argumentos invertidos (hash, password): el login nunca coincidía.

Cómo lo detecté

Con la contraseña correcta igual daba credenciales inválidas.

La solución

Lo di vuelta: compare(password, user.password).

15src/controllers/authController.jsFlujo

El problema

En login, el 401 por password incorrecta no cortaba: seguía firmando y mandando el token.

Cómo lo detecté

Revisando el flujo vi que después del 401 no cortaba.

La solución

Agregué el return faltante.

18src/controllers/userController.jsSeguridad

En updateMe el id salía de req.body.userId: se podía editar el perfil de otro usuario (IDOR).

Cómo lo detecté

La solución

Uso siempre req.user.id (el del token).

Explicación técnica

Autenticación JWT · errores 3, 4, 6, 8, 9, 10

Qué pasaba
Las rutas protegidas no protegían nada (un token inventado entraba) o directamente crasheaban.
Por qué
El módulo del token no se exportaba, se firmaba con una variable inexistente, el payload no llevaba el id, y el middleware usaba jwt.decode con una condición que dejaba pasar a cualquiera.
Solución
Corregí module.exports y JWT_SECRET, agregué el id al payload y reescribí el middleware con jwt.verify(...), cortando con 401 si no hay token o es inválido.
Validación
Sin token → 401, token inventado → 401, token válido → 200 con mi perfil.

Login · errores 11 a 15

Qué pasaba
El login nunca funcionaba con la contraseña correcta y podía tirar 500 con un email inexistente.
Por qué
bcrypt.compare tenía los argumentos al revés, varios if de error respondían sin return (seguían y mandaban una segunda respuesta) y algunos usaban códigos HTTP equivocados.
Solución
Invertí los argumentos de bcrypt.compare, agregué los return faltantes y ajusté los códigos a 400/401.
Validación
Login correcto → 200 + token; password mala → 401; email inexistente → 401 (ya no rompe).

Rutas y middlewares globales · errores 1, 2, 7, 16, 17

Qué pasaba
Register/login tiraban 500, el path de auth no existía y había rutas con datos de usuario abiertas sin autenticación.
Por qué
Faltaba express.json(), el prefijo del router tenía un typo, el orden de middlewares en /me estaba invertido, y /all y /orders no tenían el middleware de auth.
Solución
Agregué express.json() antes de los routers, corregí el prefijo a /api/auth, puse authMiddleware antes del handler en /me, y lo apliqué también a /all y /orders.
Validación
Register/login responden 201/200, y las rutas protegidas dan 401 sin token y 200 con token válido.
Nota sobre los datos. Los usuarios se guardan en memoria (src/data/db.js): al reiniciar el server se pierden los que registre. El usuario Admin del seed no se puede loguear porque solo está guardado su hash, no la contraseña en texto plano; por eso validé el flujo completo con un usuario registrado en el momento.
